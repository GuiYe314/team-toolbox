## v0.1.2 —— 自动更新：应用能自己升级了

从这一版起，team-toolbox 能自己知道有没有新版本，并把新版本装上。
不用再去发布页下载、重新安装。

### 为什么做这个

v0.1.0 的安装包在部分机器上装完起不来，修好的 v0.1.1 躺在发布页上，
用户并不知道要再去下载一次。**手动升级的实际结局是「没人升」。**

### 怎么用

「设置」→ 填更新源 → 「检查更新」→ 「下载并安装」

更新源填一个位置就行：

- GitHub：`https://github.com/GuiYe314/team-toolbox/releases/latest/download`
- 内网共享目录：`\\fileserver\share\team-toolbox`

更新时页面会短暂断开，装好后自动刷新。

### 装坏了会怎样

不会把你留在没有服务的状态：

- 换文件前**保留一份当前程序**作为回滚快照；
- 新版本启动后必须「自证成功」（删掉 pending 标记），60 秒内没删掉就判定失败；
- 自动回滚到原版本，界面上提示「上次更新没有成功，已自动回滚」。

另外三重保护：包必须与清单里的 SHA256 一致（不一致直接丢弃）、
解压防路径穿越、换文件时**明确排除 `data/`** —— 数据库与资源文件永不参与替换。
升级前还会自动把全部数据导出到 `data/updates/<版本>/pre-update-backup.zip`。

### 升级

**这一版必须手动装一次。** v0.1.1 里没有更新模块，它没法把自己升上来。
装完 0.1.2 之后，后续版本就能在应用里点一下完成。

安装包覆盖到同一目录，`data/` 默认保留，现有数据不会丢。

### 顺带修的

- **版本号漂移**：`/api/health` 此前硬编码 `0.1.0` 而 `package.json` 已是 `0.1.1`，
  等于 v0.1.1 的包对外自称 0.1.0。版本号现在收敛到一处，打包时统一注入。
- 发布前实测发现并修掉三个缺陷：发布包 zip 多一层目录导致「包结构不正确」、
  无控制台环境下 `timeout /t` 立刻返回导致**误回滚**、
  暂存目录被占用时整个解压失败。

### 下载

| 文件 | 说明 |
|---|---|
| `team-toolbox-Setup-0.1.2.exe` | 安装包（推荐） |
| `team-toolbox-0.1.2.zip` | 便携包，解压即用 |
| `team-toolbox-0.1.2-SHA256.txt` | 校验清单 |
| `manifest.json` | **自动更新读这个**，请勿删除 |

### 已知限制

- 不支持增量更新，每次下载完整包（约 71 MB）。
- 不内置默认更新源：内网与出网环境需要的源不同，写死任何一个都会让另一半用不了。
- 视频缩略图仍需服务器安装 `ffmpeg`。
