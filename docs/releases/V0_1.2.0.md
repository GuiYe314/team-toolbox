# team-toolbox 0.1.2 发布说明

## 这个版本带来什么

**自动更新**。从这一版起，应用能自己知道有没有新版本，并把新版本装上 ——
不用再去发布页下载、重新安装。

这是第一个**依赖它自己**来解决「没人升级」问题的版本，
所以安装方式要单独说明（见「升级说明」）。

### 为什么需要它

v0.1.0 的安装包在部分机器上装完起不来，修好的 v0.1.1 躺在发布页上，
用户并不知道要再去下载一次。手动升级的实际结局是「没人升」。

### 怎么用

1. 打开「设置」（侧栏最后一项）
2. 在「更新源地址」里填一个位置，例如：
   - GitHub：`https://github.com/GuiYe314/team-toolbox/releases/latest/download`
   - 内网共享目录：`\\fileserver\share\team-toolbox`
3. 点「检查更新」→ 有新版时点「下载并安装」

更新过程中页面会短暂断开，装好后自动刷新。

详细的运维说明（更新源怎么放文件、出问题怎么查）见
[docs/AUTO_UPDATE.md](../AUTO_UPDATE.md)。

## 更新时做了什么

```
检查 → 下载（边下边算 SHA256）→ 解压 + 用包内 node.exe 自检
     → 备份全部数据 → 独立进程换文件 → 重启
                                    ↓ 60 秒内未确认启动成功
                                 自动回滚
```

几个刻意的保证：

- **数据永不参与替换**：换文件时明确排除 `data/`，数据库、图片、资源文件都不会被碰到。
- **装坏能退**：换文件前保留一份当前程序，新版本起不来会自动退回原版本，
  并在界面上提示「上次更新没有成功」。
- **包必须对得上**：SHA256 与清单不一致直接丢弃，不安装。
- **装前自动备份**：升级前把文档、文档图片、资源文件全部导出到
  `data/updates/<版本>/pre-update-backup.zip`。

## 升级说明

**这一版必须手动装一次。** v0.1.1 里没有更新模块，它没法把自己升上来。
装完 0.1.2 之后，后续版本就能在应用里点一下完成升级。

安装包会覆盖到同一目录，`data/` 默认保留，**现有数据不会丢**。
为稳妥起见，升级前仍建议做一次全量备份（知识库 → 导出 → 全量备份）。

## 顺带修掉的问题

- **版本号漂移**：此前 `/api/health` 硬编码 `0.1.0`，而 `package.json` 已是 `0.1.1`，
  等于 v0.1.1 的包对外自称 0.1.0。现在版本号收敛到 `package.json` 一处，
  打包时统一注入。
- 更新相关的三个缺陷（发布包多一层目录、无控制台环境下延时失效导致误回滚、
  暂存目录被占用时解压失败）均在发布前实测发现并修复。

## 已知限制

- **不支持增量更新**：每次更新下载完整包（约 71 MB）。内网千兆下是几秒钟。
- **更新源需要自己准备**：本版不内置默认更新源 —— 内网环境与能出网的环境
  需要的源不一样，写死任何一个都会让另一半用户用不了。
- 视频缩略图仍不可用（需要服务器安装 `ffmpeg`，原始文件不受影响）。

## 校验

安装包与便携包的 SHA256 见同页的 `team-toolbox-0.1.2-SHA256.txt`。
自动更新用的校验值在 `manifest.json` 里，两者一致。
