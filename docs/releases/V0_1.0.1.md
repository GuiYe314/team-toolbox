# team-toolbox 0.1.1 发布说明

## 这个版本修的是什么

**v0.1.0 的发布包在部分机器上装完根本起不来。** 本版本修复该缺陷。

### 症状

双击 `启动.cmd` 后报错并退出：

```
Error: 无法打开数据库，请检查配置
    code: 'cannot_open',
    detail: '[Cannot open] The module '\\?\C:\...\better_sqlite3.node'
             was compiled against a different Node.js version using
             NODE_MODULE_VERSION 127. This version of Node.js requires
             NODE_MODULE_VERSION 137. Please try re-compiling or
             re-installing'
```

### 原因

`better-sqlite3` 是 **NODE_MODULE_VERSION 敏感**的原生模块——随包分发的
`.node` 二进制只能被**同 ABI** 的 Node 加载：

| Node 版本 | ABI |
|---|---|
| Node 22 | 127 |
| Node 24 | 137 |

打包时依赖是在**构建机（Node 22）**上安装的，因此随包的二进制是 ABI 127。
如果你的机器上装的是 Node 24（或其他不同版本），加载就必然失败。

这不是「用户装错了」——发布包本就不该依赖用户机器的 Node 版本。

### 为什么不能靠 `npm rebuild` 让用户自己修

`better-sqlite3` v11.10.0 官方预编译包只覆盖 `node-v108 / v115 / v127 / v131`，
**没有 Node 24（ABI 137）**。用户机器上重新安装只会退化成源码编译，
需要 Visual Studio Build Tools —— 对一个「双击即用」的工具来说不可接受。

### 修复方式

**发布包内自带 Node 运行时**（`runtime/node.exe`，v22.22.2）。

- 启动脚本**优先**使用内置运行时，完全不受用户系统 Node 版本影响；
- 用户机器上**不需要安装 Node.js**；
- 安装器的「未检测到 Node.js」提示已移除（它挡不住真正的问题）；
- 启动前有**运行时自检**（`runtime/check.js`）：若随包依赖被换成别的 Node
  版本编译的二进制，会给出可操作的提示，而不是把用户直接甩给一段堆栈。

体积代价：ZIP 从 41.2 MB 增至 74.4 MB，安装包从 27.6 MB 增至 49.0 MB。

## 下载与安装

| 文件 | 大小 | 说明 |
|---|---|---|
| `team-toolbox-Setup-0.1.1.exe` | 49,030,266 字节 | 安装包（推荐） |
| `team-toolbox-0.1.1.zip` | 74,437,577 字节 | 便携包，解压即用 |
| `team-toolbox-0.1.1-SHA256.txt` | 373 字节 | 校验清单 |

安装后位于 `%LOCALAPPDATA%\team-toolbox`，双击 `启动.cmd` 启动。

## 升级说明

- **从 v0.1.0 升级**：直接运行新版安装包覆盖安装即可。
  两者安装目录相同，卸载程序会替换旧文件。
- **数据不受影响**：`data\` 目录不在覆盖范围内，卸载也保留数据。
- 若 v0.1.0 装完后初始化失败，`data\team-toolbox.sqlite3` 可能不存在或为空 ——
  新版首次启动会自动重建并应用全部迁移。

## 已知限制

- **视频无缩略图**：本机未安装 ffmpeg 时，视频资源没有封面。
  原始文件可正常上传下载，不影响功能。
- **无账号与权限**：部署假设仍是受控内网/本机，**不可暴露到公网**。

## 校验

```bash
certutil -hashfile team-toolbox-Setup-0.1.1.exe SHA256
# 或
sha256sum team-toolbox-Setup-0.1.1.exe
```
