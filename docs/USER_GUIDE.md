# 用户指南（USER_GUIDE）

## 0. 使用发布包（推荐，无需安装 Node.js）

> 本节描述**普通使用者**的用法。开发环境的说明见第 4 节。

### 0.1 安装

下载 `team-toolbox-Setup-<版本>.exe` 双击安装，安装向导会把它放在
`%LOCALAPPDATA%\team-toolbox`。**不需要预先安装 Node.js** ——
发布包内已内置运行时（v0.1.1 起）。

也可以下载 `team-toolbox-<版本>.zip` 解压即用，无需安装。

### 0.2 启动与停止

- **启动**：双击安装目录下的 `启动.cmd`。窗口显示运行时自检和启动进度；
  后端及数据库就绪后，浏览器自动打开 `http://127.0.0.1:3000/`，启动 CMD 自动关闭，服务继续在后台运行。
- **停止**：双击同目录的 `停止.cmd`，按该项目的绝对路径识别并关闭后台服务。关闭网页不会停止服务。
- **启动失败**：窗口保留错误摘要并等待按键，输出和错误保存在安装目录 `logs/backend.log` 与 `logs/backend-error.log`；下次启动各保留一份 `.previous`。

### 0.3 数据在哪里

所有数据在 `%LOCALAPPDATA%\team-toolbox\data\`：

| 内容 | 路径 |
|---|---|
| 文档数据库 | `data\team-toolbox.sqlite3` |
| 资源文件（原图、模型、预览图） | `data\assets\` |
| 本机 ADB 路径配置 | `data\android-adb.json`（机器配置，不包含在团队内容备份中） |
| 本机自定义 ADB 命令 | `data\android-commands.json`（机器配置，不包含在团队内容备份中） |

**卸载不会删除 data 目录** —— 数据保留，重装后仍在。
要彻底清理请手动删除整个安装目录。

### 0.4 备份（重要）

在知识库页「导入导出」里选 **「全量备份（.zip）」**。
这是唯一包含资源文件的备份格式（另两种 JSON 格式只含文档文字）。

建议在重要变更后手动导出一次。备份文件请按内部资料保管。

### 0.5 遇到问题

| 现象 | 原因与处理 |
|---|---|
| 提示「运行时自检」失败 | 随包的数据库驱动与 Node 版本不匹配 —— 通常是在包内跑过 `npm install`。重新下载完整发布包即可。 |
| 提示端口被占用 | 端口已有程序使用。本目录已有实例时运行 `停止.cmd` 后重试；若仍占用，检查原占用程序，启动脚本不会替你结束其他程序。 |
| CMD 关闭了但服务仍可访问 | 启动成功后后台运行是正常行为，需要停止时双击 `停止.cmd`。 |
| 视频没有封面 | 本机未安装 ffmpeg。原始文件可正常上传下载，只是没有缩略图。 |

### 0.6 局域网访问

- 包含 TASK-035 的启动器默认为 **Lan**：源码版 `start.bat` 同时启动前后端，页面使用 `http://服务器IPv4:5173/`；发布版 `启动.cmd` 使用 `http://服务器IPv4:3000/`。使用启动信息中实际显示的私网地址，端口可按配置改变。服务器本机仍可访问 localhost，启动成功后 CMD 自动退出。
- 全部工具均可使用，包含 ADB、APK 单台/多台安装、屏幕和应用日志、Unity 日志，以及三个开源接入。ADB、Unity 搜索、组件下载和 ArtCraft 进程都在工具箱服务器执行；填写路径也指服务器。APK 选择和“保存到电脑”由当前浏览器处理。
- 仅本机使用时，先停止已有实例，再执行 `start.bat /local`（发布入口为 `启动.cmd /local`）。PowerShell 辅助脚本对应 `-AccessMode Local`；`TT_ACCESS_MODE=Local` 也可指定。直接通过 Node/npm 启动仍默认 Local；手工配置 Lan 须同步启用前后端的 `TOOLBOX_ALLOW_LAN=1`、监听地址及一致的代理端口，见两份 `.env.example`。
- 客户端须在服务器实际私网网卡掩码覆盖的同网段，使用服务器私网 IPv4；公网、陌生域名、跨站工具请求和伪造转发头被拒绝。不同网段、VPN 或反向代理需要单独规划，不能仅修改 Host 绕过限制。
- 远程打不开时，先检查服务器启动是否成功、IP/端口是否正确、两端是否同网段及 Wi-Fi 隔离。Windows 防火墙只放行需要的工具箱端口和可信网段（开发页面默认 TCP 5173，发布页面 TCP 3000）；不要关闭整个防火墙或设置公网端口映射。
- 当前没有账号与权限；同网段可访问者共用服务器配置、设备和后端内存 Key，可能互相影响采集及独占任务，仅用于可信内网。FreeLLMAPI 管理页在服务器电脑打开，模型对话通过工具箱网页使用；ArtCraft 原生窗口也在服务器电脑显示。HTTP 复制有浏览器兼容路径，浏览器仍拒绝时可手动复制。

### 0.7 程序更新

打开“设置 → 更新源地址”，点击“使用项目 GitHub”，即可从 [本项目](https://github.com/GuiYe314/team-toolbox) 的最新正式 Release 获取更新。首次无配置默认使用项目源；此前已关闭或自定义的配置继续保留。也可以直接粘贴仓库网址或以 `.git` 结尾的 HTTPS 地址，保存后自动转换为 `https://github.com/GuiYe314/team-toolbox/releases/latest/download`。

点击“检查更新”，发现新版后核对说明并选择“下载并安装”。程序会校验完整 ZIP、自检运行时、备份数据并重启，页面短暂断开后自动刷新；新版本未启动成功时自动回滚。仅上传 Git 源码不会形成可安装更新，发布者必须同步上传 ZIP 与 `manifest.json`。

“关闭更新”会保存关闭状态，不再允许检查；可随时用“使用项目 GitHub”恢复。更新器支持代理环境变量或 Windows 手动 HTTP/HTTPS 代理；不能访问 GitHub 的环境可填写内网共享目录或 HTTP 静态源。由 `UPDATE_SOURCE` 指定的源优先，界面按钮会禁用。旧版本在需要代理或无控制台/中文路径环境中可能更新失败，可先备份数据并手动安装 v0.3.1。详细运维说明见 [AUTO_UPDATE](AUTO_UPDATE.md)。

## 1. 预期使用场景

内部小团队在受控内网（或本机）通过浏览器访问 team-toolbox：用知识库沉淀 Markdown 文档；首页浏览最近更新；通过分类、标签与搜索查找内容。小工具入口包括比例锁定与安卓无线调试；全部工具可通过局域网地址访问，服务器仍负责 ADB 和 Unity 设备操作，详见第 0.6、6 节。

## 2. 知识库与工具操作

### 2.1 新建文档
1. 进入“新建文档”页；2. 填写标题（必填）与 Markdown 正文；3. 可选选择分类、添加标签；4. 点击“保存”后跳转到文档页。
- 保存失败（网络/服务错误）时：页面会保留已输入内容，可直接重试；此时**不要关闭或刷新页面**，否则草稿可能丢失。

### 2.2 编辑文档
1. 打开文档并进入“编辑”；2. 修改内容后“保存”。
- 若提示“文档已在别处被修改”（保存冲突）：请选择【加载最新】（放弃本地修改）或【基于最新覆盖保存】。系统**不会自动合并**，建议先复制本地修改到安全位置，再加载最新并比对后决定。

### 2.3 删除文档
1. 文档页点击“删除”；2. 在确认框中二次确认后才会删除。
- 删除不可撤销；误删请联系管理员从备份恢复（见 [ARCHITECTURE](ARCHITECTURE.md) 第 6 节）。

### 2.4 分类与标签
- 在编辑页选择或新建分类（一级，不支持嵌套）；重命名分类不影响文档归属；删除分类后其中文档变为“未分类”。
- 标签在编辑页输入，重复会自动合并；在列表页可按标签过滤文档。

### 2.5 搜索
- 在搜索框输入关键词，将匹配文档标题与正文，结果按更新时间倒序排列；无结果时会显示空状态提示，而非报错。

### 2.6 首页与工具入口
- 首页默认显示“最近更新”（标题、分类、标签、更新时间），可“查看更多”。
- “小工具”区块展示工具卡片；点击尚未实现的工具会进入空状态页，明确提示“该工具尚未实现”，不会出现模拟结果。进入“工具箱”页面后可直接拖动卡片调整前后顺序：移到目标卡片左半区放在前面，右半区放在后面；高亮边缘显示放置位置。顺序保存在当前浏览器，首页已有工具也跟随相对顺序；点击“恢复默认顺序”可重置。浏览器无法保存时会明确提示，可允许此网站保存数据后重试。不同浏览器、电脑及访问地址各自保留排序；该排序是界面偏好，不改变工具数据或团队数据库。

## 3. 使用边界与数据须知

- **仅在受控内网使用**：系统第一版无账号与权限，切勿将其暴露到公网。
- **数据在服务端**：所有团队文档保存在服务器上，任何成员在任何设备/浏览器访问同一地址看到的是同一份数据；浏览器本地不保存团队数据。
- **重要变更后建议备份**：由管理员手动触发导出（MVP 为手动备份）。

## 4. 本机启动（已验证）

> 以下命令在 **2026-10-16 Windows + Node.js v22.22.2（npm 10.9.7）** 上实际执行并通过验证。生产部署不在本阶段范围。

### 4.1 前置

- 已安装 Node.js ≥ 20.19（推荐 v22 LTS，本项目已用 v22.22.2 验证）。
- Node.js v24.19.0 与现有 SQLite 原生模块在部分测试中会触发 `RemoveEnvironmentCleanupHook` 崩溃；本次完整后端测试使用 v24.22.1 通过。使用 Node 24 时请避开 v24.19.0。
- 已克隆仓库到本机。
- 不需要任何外部数据库或服务。

### 4.2 准备配置（每个子项目一次）

```
# backend/.env（参考 backend/.env.example，**真实 .env 不入库**）
HOST=127.0.0.1
PORT=3000
DB_PATH=data/team-toolbox.sqlite3

# frontend/.env（参考 frontend/.env.example）
VITE_DEV_HOST=127.0.0.1
VITE_DEV_PORT=5173
VITE_API_BASE=/api
```

### 4.3 安装依赖

```
cd backend
npm install

cd ../frontend
npm install
```

实际验证摘要：后端安装 117 个包（耗时约 26s，含 better-sqlite3 prebuilt 二进制）；前端安装 36 个包（耗时约 1m，含 Vite 6 与 Vue 3）。

### 4.4 初始化数据库（首次或升级迁移时）

```
cd backend
npm run migrate
```

实际验证摘要：首次运行输出 `[migrate] applied 001_init.sql`，数据库 `data/team-toolbox.sqlite3` 创建；二次运行 `applied_in_this_run=0`，证明迁移幂等。

### 4.5 启动后端

也可以直接双击根目录 `start.bat`，自动检查依赖并同时启动后端和 Vite；两者就绪后打开网页、关闭启动 CMD，服务在后台运行。失败时窗口保留摘要；日志位于 `logs/backend.log`、`logs/backend-error.log`、`logs/frontend.log` 和 `logs/frontend-error.log`，每次启动轮换上一份。若希望直接查看控制台输出，分别执行下述后端和第 4.6 节的前端命令。

```
cd backend
npm start          # 或 npm run dev（Node --watch 自动重启）
```

实际验证摘要：控制台输出 `[server] listening on http://127.0.0.1:3000` 与 `node: v22.22.2`。`GET /api/health` 返回 200：

```json
{"status":"ok","service":"team-toolbox-backend","version":"0.1.0","db":{"path":"...team-toolbox.sqlite3","ok":true,"size_bytes":53248}}
```

### 4.6 启动前端（开发模式）

```
cd frontend
npm run dev        # 或 npm run build 后 npm run preview
```

实际验证摘要：Vite 启动后输出 `VITE v6.4.4 ready in 1631 ms`，HTTP `http://127.0.0.1:5173/` 返回 200；`/src/main.js`、`/src/App.vue` 模块均 200；`/api/*` 由 Vite proxy 转发到后端 `http://127.0.0.1:3000`，已通过 `GET /api/health` 与 `POST /api/_dev/render-markdown` 验证联通。

### 4.7 关闭

- 使用根目录 `start.bat` 启动时，双击同目录 `stop.bat` 可关闭本项目的后台后端、前端服务及其子进程，数据文件会保留。启动与关闭入口需要保留 `scripts/start-services.ps1` 和 `scripts/stop.ps1`。
- `stop.bat /nopause` 可跳过结束时的按键等待；服务未运行或重复关闭时返回成功，查询或关闭失败时显示错误并返回非零退出码。
- 进程按当前项目的绝对路径识别；其他目录的项目保持运行。脚本也识别使用绝对入口路径启动的后端与 Vite 服务。
- 手动在终端使用相对路径启动服务时，在后端、前端对应的终端分别按 `Ctrl+C` 关闭；后端支持 SIGINT/SIGTERM 优雅关闭。

## 5. 当前限制（截至阶段一 TASK-001 完成）
- 无账号与权限区分：能访问内网页面的人即可读写全部文档。
- 无实时协同：多人同时编辑同一文档会触发保存冲突，需人工处理，不会自动合并。
- 无回收站：删除操作需谨慎。
- 以上限制的解决（实时协同 F-COL-001、账号权限 F-SEC-001）均已规划为延期特性，详见 [FUNCTIONAL_SPEC](FUNCTIONAL_SPEC.md) 第 4 节。

## 6. 安卓无线调试

### 6.1 准备

- 在运行工具箱后端的电脑安装 [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools)，ADB 不随工具箱分发。
- 手机使用 Android 11 及以上系统，打开“开发者选项 → 无线调试”，并与电脑连接同一局域网。
- 用启动器显示的局域网地址打开“工具箱 → 安卓无线调试”；服务器本机仍可使用 localhost。手机需与工具箱服务器互通，ADB 路径填写服务器上的文件夹。
- 连接步骤、配对说明与故障处理默认收起，点击页面顶部“帮助”打开弹窗；点击“关闭”、遮罩空白处或按 Escape 关闭。
- 页面左侧为设备连接与列表，右侧为常用命令、手机屏幕与设备日志，两栏可以分别滚动。下拉框与选项使用明暗主题对应的实底配色。

### 6.2 输入文件夹搜索 ADB

1. 点击调试页顶部“ADB 设置”打开弹窗；普通设置页的“安卓调试”卡片也提供同一入口。填写服务器上的文件夹，例如 `C:\Android\platform-tools` 或它的上级 `C:\Android`，点击“搜索并配置”。不用输入 `adb.exe` 文件名，也不用上传文件。
2. 搜索包含子文件夹。找到一个 ADB 时，自动校验版本并保存；找到多个时，在候选列表选择所需路径，点击“使用此 ADB”。没有找到时会明确提示，保留原配置。
3. “当前使用”展示实际找到的可执行文件路径。“清除配置”可移除保存的路径；刷新页面后输入框显示当前 ADB 所在文件夹。
4. 点击“关闭”、遮罩空白处或按 Escape 关闭弹窗，不跳转页面。在调试页保存配置后立即刷新配置状态，并清除旧设备、发现服务、屏幕画面和日志；重新刷新设备即可使用新配置。

扫描最多向下六层，受目录数、条目数和时间限制，不进入链接目录或依赖目录。提示未完整扫描时，选择更靠近 `platform-tools` 的文件夹后重试。

配置写入服务器项目目录下 `data/android-adb.json`，不进入团队内容备份。管理员也可设置 `backend/.env` 的 `ADB_PATH` 环境变量；该变量优先，设置后页面无法修改路径。

### 6.3 扫码自动配对并连接

1. 点击“生成配对二维码”。
2. 在手机进入“开发者选项 → 无线调试 → 使用二维码配对设备”，扫描电脑页面中的二维码。请使用这个专用入口。
3. 保持页面打开，工具箱会自动发现刚扫码的手机、配对并连接，成功后刷新设备列表。无需输入六位配对码或 IP。

二维码两分钟有效，页面显示剩余时间；可点击“取消扫码”，到期或失败后可重新生成。取消、离开页面或结束会话会隐藏二维码并清理临时口令；网络中断时服务器会在到期后清理。口令不写入配置或日志。已完成配对后取消会话不会移除手机已经保存的配对记录。

配对成功但连接服务尚未出现时，页面会继续等待；等待超时可通过下面的服务搜索或手动地址连接。发现多个无法区分的连接服务时，页面提示手动选择。

### 6.4 六位码备用配对

1. 在手机的无线调试页面选择“使用配对码配对设备”，保持此页面打开。
2. 点击“搜索无线设备”，找到与手机配对页面地址一致的“配对服务”，点击“配对”，填写六位数字码并确认。
3. 配对成功后页面重新搜索，选择“连接服务”并连接；也可在连接框填写手机无线调试主页显示的 `IPv4:连接端口`。

配对端口与连接端口不同；配对码输入框提交后立即清空，不保存到配置或日志。搜索结果中的配对服务有效期为两分钟，过期时重新搜索。

### 6.5 设备管理

- “刷新设备”显示 USB、无线 ADB、模拟器、型号和授权状态。未授权时需要在手机上确认；离线时检查手机无线调试和网络。
- 连接成功后自动刷新设备列表。若连接成功但刷新失败，页面会分别说明结果，可稍后手动刷新。
- 对所需无线设备点击“断开”，核对序列号后“确认断开”。取消时保持连接；不会全局断开其他设备。
- 已配对设备可直接填写当前连接地址重连。重启手机、切换网络或重新打开无线调试后，端口可能变化，请以手机当前显示的地址为准。

### 6.6 常用 ADB 命令

1. 连接手机，点击“刷新设备”。在右侧“常用 ADB 命令”的“目标设备”中选择要操作的设备，只能选择已连接并授权的设备。
2. 选择命令，查看说明与命令预览，点击“执行”。仅选择选项不会执行命令。
3. 结果区显示目标序列号、执行状态、标准输出与标准错误。更换设备或命令会清除旧结果；结果仅保留在当前页面。

| 分类 | 内置命令 |
|---|---|
| 程序与桌面 | 锁定程序、解锁程序（恢复桌面） |
| 设备查询 | 获取 IP、设备信息 |
| 运行情况 | 手机内存使用、CPU 使用 |

内置命令仅保留以上六项。“获取 IP”查询所有接口的 IPv4 地址，可能包含 Wi-Fi、移动网络和回环地址；“设备信息”整理厂商、品牌、型号、Android 版本、SDK 和 CPU 架构。“手机内存使用”读取 `dumpsys meminfo` 的 RAM 与进程信息，“CPU 使用”读取 `dumpsys cpuinfo` 的采样快照；再次执行可更新结果，采样时段由手机系统提供。

#### 锁定程序与恢复桌面

1. 选择“锁定程序”，等待读取手机当前 Android 用户、实际提供 HOME 入口的应用和当前默认桌面。先记下原桌面，便于恢复。
2. 按包名或组件搜索，主动选择目标程序。列表不会自动替你选择；未选择时无法执行。
3. 点击“执行”，核对设备序列号及预览中的 `--user` 和应用组件，再点击“确认设置”；取消不发送修改。实际调用 `adb -s <设备> shell cmd package set-home-activity --user <当前用户> <组件>`。
4. 手机返回成功后，工具重新读取默认 HOME 并核对目标包，更新界面。按手机主页键进入所选程序；工具不会自动启动程序。
5. 恢复时选择“解锁程序（恢复桌面）”，重新选择原桌面并确认设置。此操作将所选桌面恢复为当前用户的默认 HOME。

这里的“锁定”表示设为默认桌面，不能禁止系统手势或退出应用。普通应用必须先在 Android 配置中声明 HOME 入口才会出现在列表。当前用户改变、应用移除或不再提供 HOME 入口时，服务器拒绝沿用旧选择；点击“重新读取应用”后重新选择。系统或厂商限制可能导致命令失败，查看具体原因后重试；读取与设置均有超时及输出上限。切换目标或命令、修改 ADB 配置及离开页面会清除对应的临时选择和结果，不保存到团队数据。

#### 自定义常用命令

1. 点击命令区右上角“添加命令”，填写名称、分类、命令参数及可选说明。参数只填写 `adb` 后的部分，例如 `shell dumpsys meminfo com.example.app`；系统自动指定目标设备，不用填写 `adb` 或 `-s`。
2. 点击“保存命令”。保存后按分类加入下拉列表并选中，不会自动执行。尚未配置 ADB 或连接手机时也可管理命令。
3. 选择在线设备，点击“执行”，核对确认区的设备序列号和完整命令，再点击“确认执行”。每次自定义执行都需要确认；取消时不发送命令。
4. 选择自定义命令后可点击“编辑”修改；取消或按 Escape 放弃草稿，保存失败保留输入内容。“删除”需再次确认，只移除该配置。内置命令不可编辑或删除。

例如可添加以下设备命令，应用包名按实际项目修改：

| 名称 | 命令参数 |
|---|---|
| 应用内存快照 | `shell dumpsys meminfo com.example.app` |
| 应用启动页面 | `shell am start -n com.example.app/.MainActivity` |
| 日志快照 | `logcat -d -t 100` |

含空格的单个参数用单引号或双引号包裹，例如 `shell input text "hello world"`。支持以 `shell`、`reboot`、`get-state`、`get-serialno`、`get-devpath`、`features`、`logcat` 开头的单条命令，不支持全局连接参数、管道、重定向或多条拼接。持续日志请使用“设备日志”；命令执行沿用 20 秒和 256 KiB 输出限制。

最多保存 100 条，名称最多 60 字、分类 30 字、说明 400 字、参数 2048 字。配置原子保存至服务器 `data/android-commands.json`，重启后保留，不属于团队内容备份。其他页面修改命令后，旧版本不会执行；点击“重新读取命令”核对最新内容。执行结果仅留在当前页面。

### 6.7 实时设备日志（Logcat）

1. 在右侧“设备日志”选择已连接并授权的设备，点击“开始采集”。先读取最近约 100 条日志，再持续获取新日志；不会自动开始采集。
2. 日志显示时间、进程/线程、级别、标签和正文。通过“最低级别”和“关键词”筛选，按需开启“自动滚动”；采集时仍可执行常用 ADB 命令。
3. “清空显示”只清除页面内容，继续接收新日志，不清空手机日志缓冲区。“停止采集”终止 ADB 日志进程并保留当前显示结果；再次开始会清空旧结果。

切换日志设备、离开调试页、修改 ADB 配置或对应设备断开/重启时停止采集。页面超过 15 秒没有轮询时，服务器也会终止进程；恢复后可重新开始。日志只在内存中，不自动保存到磁盘、配置或团队备份。服务端缓存最多 2000 条或 1 MiB，页面最多显示 2000 条，旧日志自动轮换，过长单行会截断。

### 6.8 查看单个 App 的运行情况

1. 在“设备日志”选择在线设备，把“日志范围”从“设备全部日志”改为“指定应用”。页面读取已安装应用包名，不需要输入 ADB 命令。
2. 在“搜索应用包名”中搜索，例如项目的 Android 包名，选择对应应用。显示“运行中 / 未运行”、当前匹配的进程号与最后检查时间；可点击“刷新状态”主动重读。运行中表示存在进程，不代表应用在前台。
3. 点击“开始采集”，只接收匹配主进程及 `包名:子进程` 的日志。采集中约每两秒检查进程变化；应用未运行时可以先开始等待，再在手机上打开应用。退出后继续等待，重启后跟随新 PID。
4. 仍可按级别和关键词筛选、停止或清空显示。切换应用、日志范围或设备时停止旧采集并清空旧结果；要看系统和其他进程的相关记录，切回“设备全部日志”。

应用列表、包名选择与运行状态只保留在当前页面；不自动启动、停止或修改手机应用。仅选择应用时读取一次状态，采集期间自动更新，停止后显示最后一次快照。

日志按最近检查到的进程号筛选：短于检查间隔就结束的进程、自定义为其他名称的进程和系统进程代写的记录可能无法捕获，也不补录已退出的历史进程日志。应用自己没有输出日志时，专属日志可以为空。

### 6.9 网页查看手机屏幕

1. 连接手机并刷新设备，在右侧“手机屏幕”的“屏幕设备”中选择已连接、已授权的目标。页面默认不读取画面。
2. 点击“刷新画面”读取一次当前屏幕；或选择 1、2、5 秒的刷新间隔，点击“开始连续刷新”。每轮读取完成后才等待所选间隔再读取，避免请求重叠；实际间隔还包含截图和传输时间。
3. 点击“停止读取”结束当前读取和连续刷新，保留最后画面、尺寸与读取时间；点击“清空画面”停止并移除图片。停止后的画面是最后一次快照。
4. 点击“放大查看”打开居中弹窗。点击“关闭”、遮罩空白处或按 Escape 返回；连续刷新中的画面也会同步到放大弹窗。

切换屏幕设备、设备从列表消失、修改 ADB 配置或离开调试页时，会取消读取并清空旧画面。页面进入后台时停止读取，保留最后快照；返回页面后按需重新开始。读取失败时显示原因并停止连续刷新，可检查连接后重试。

截图只在内存中，不自动保存到磁盘或团队备份。此功能通过连续截图查看屏幕，速度取决于 ADB、设备及网络；操作仍在手机上进行。受保护应用或页面可能显示黑屏。访问范围与其他 ADB 功能相同，Lan 模式允许同网段浏览器通过工具箱地址查看。

### 6.10 传送 APK 并安装

1. 先连接手机并刷新设备。在右栏“APK 传送安装”选择状态为已连接的设备，支持无线、USB 或模拟器。
2. 点击“选择文件”，从电脑选取单个完整 `.apk`。点击“传送并安装”，核对文件名、大小及目标设备，再点击“确认安装”。选择文件或取消确认都不会安装。
3. 上传百分比表示浏览器向工具箱传送文件；随后等待校验及 ADB 传送安装，只有设备返回成功才显示“APK 安装成功”。手机若弹出安装确认，需在手机操作。
4. 安装失败时查看错误原因，所选文件会保留，可再次确认重试。需要换文件时选择新文件或点击“清除文件”。

**安装到多台手机**：勾选“多设备安装”，逐个勾选在线设备，或点击“全选在线设备”（每批最多 20 台，超过时可选择前 20 台）。选取同一个 APK，点击“安装到 N 台设备”，核对确认区内的文件和全部手机型号、序列号，再点击“确认安装”。取消全选或更换目标后需重新确认。

APK 向工具箱只上传一次，随后按所选顺序逐台安装。页面实时显示每台的等待、安装中、成功或失败状态及失败原因，最后分别汇总成功与失败数量。单台安装失败、离线、未授权或超时会继续下一台；点击“只选择失败设备”仅重新勾选当前在线的失败设备，核对后再次确认，不会自动重装已经成功的手机。

使用 `adb -s <所选设备> install -r` 覆盖同包名应用，保留应用数据，不自动打开应用、降级或卸载。签名不一致、版本过低、空间不足及厂商安装限制均可能导致失败，先提供兼容安装包或检查手机设置。

最多传送 1 GiB 的完整 APK，不支持直接安装 AAB、APKS 或拆分包集合。临时安装包在操作结束后清理，不写入团队数据库或备份；上传最多五分钟，每台手机的 ADB 检查及安装最多五分钟。

点击“取消操作”或离开页面会停止当前操作及尚未执行的设备队列；已收到的成功结果会保留在当前页面，取消不能撤销手机已经完成的安装，未收到最终结果的设备需在手机核对。切换设备或配置后需重新核对目标，返回页面不会保留旧文件、批量选择及安装结果。

### 6.11 常见问题

| 现象 | 处理 |
|---|---|
| 提示访问受限 | 用默认 Lan 模式重启前后端，使用服务器实际局域网 IP；客户端须在服务器网卡同网段，不能使用公网代理或陌生域名。 |
| 文件夹中未找到 ADB | 先解压 Platform-Tools，填写包含 `adb.exe` 的文件夹或它的上级目录；缩小搜索范围后重试。 |
| ADB 版本校验失败 | 核对所选候选是否来自 Platform-Tools，以及读取/运行权限。 |
| 扫码后一直等待 | 使用手机无线调试的专用二维码入口，确认同一局域网；路由器隔离或屏蔽 mDNS 时无法自动发现，检查网络或改用六位码配对。 |
| 二维码过期 | 点击“生成配对二维码”获取新的二维码，再在手机的无线调试入口扫描。 |
| 未发现配对服务 | 保持手机配对码页面打开，确认同一局域网；路由器隔离或屏蔽 mDNS 时无法发现服务。 |
| 配对码过期或失败 | 重新打开手机配对码页面，重新搜索并输入当前六位码。 |
| 已配对但连接失败 | 使用无线调试主页的连接端口，核对 IP；检查网络、防火墙与手机屏幕中的授权提示。 |
| 设备列表为空 | 检查连接状态后手动刷新。设备列表是服务器电脑的 ADB 视图。 |
| 命令目标不可选 | 先连接和授权设备，再刷新设备列表；离线或未授权设备不能执行常用命令。 |
| 常用命令失败 | 核对目标仍在线，查看错误原因；系统或厂商可能限制部分调试命令。 |
| APK 提示签名不一致或版本过低 | 使用与原应用签名一致且版本兼容的安装包；工具不会自动卸载、清除数据或强制降级。 |
| APK 上传完成但未显示成功 | 上传后还需等待 ADB 传送安装，检查手机安装确认、无线连接和剩余空间。 |
| APK 操作取消或超时 | 在手机核对是否已经安装，再决定是否重试；取消不能回滚已经完成的安装。 |
| 批量安装部分失败 | 查看每台结果与原因；连接并刷新失败设备后，点击“只选择失败设备”，核对目标再重新确认安装。 |
| 锁定程序中找不到应用 | 此列表只显示当前用户实际提供 HOME 入口的应用；普通启动 Activity 不能直接设为默认桌面。 |
| 提示当前用户或应用已变化 | 点击“重新读取应用”，核对用户并重新选择程序或桌面，再确认。 |
| 日志为空 | 核对目标设备、级别和关键词筛选；等待设备产生新日志。 |
| 日志采集中断 | 查看错误原因，确认设备在线；切换网络、修改配置或页面长时间无响应后重新开始采集。 |
| 不知道应用包名 | 可在 Android 项目配置中查看；也可用包名搜索列表，当前列表按包名展示，不显示应用图标或中文名称。 |
| 应用显示未运行 | 先在手机打开应用，再点击“刷新状态”，或开始采集等待启动；此功能不会自动启动手机应用。 |
| 专属日志缺少记录 | 核对包名及筛选条件；仅采集当前匹配进程的输出，系统代写、特殊进程名或极短暂进程可切回设备全部日志排查。 |
| 屏幕读取失败或超时 | 确认所选设备仍在线并已授权，检查无线连接后重试；画面有大小和读取时间限制。 |
| 屏幕刷新较慢 | 每轮完成后才等待所选间隔；无线网络、设备截图速度和画面大小都会影响速度。 |
| 屏幕中部分内容黑屏 | 受保护应用可能禁止截图；切换到手机主页核对显示。 |

二维码遵循 [Android 官方 ADB Wi-Fi 协议](https://android.googlesource.com/platform/packages/modules/adb/+/HEAD/docs/dev/adb_wifi.md)。模块提供连接、配对、设备管理、常用命令、APK 传送安装、实时 Logcat、单应用运行状态与日志，以及网页屏幕预览。真实手机验证情况见 [项目状态](PROJECT_STATUS.md)。

### 6.12 查看 APK 包名

1. 打开“安卓无线调试”，在右侧找到“查看 APK 包名”。此功能无需完成手机连接或 ADB 设置。
2. 选择电脑上的单个 `.apk` 文件，点击“读取包名”。先显示上传进度，再读取安装包根清单；单文件最多 1 GiB，不支持 AAB/APKS。
3. 读取完成后显示应用包名，例如 `com.example.app`。点击“复制包名”，也可选中结果输入框手动复制，用于应用日志搜索或其他包名操作。
4. “清空”移除当前文件和结果，“取消读取”结束当前等待；切换文件会清除旧结果，页面进入后台或离开页面会取消读取。取消后可重试。

支持标准编译后的 UTF-8/UTF-16 AndroidManifest.xml。损坏文件、加密或重复清单、非字符串包名会明确报错；读取包名不代表签名或可安装性验证。APK 在运行工具的电脑上临时保存，结束、失败或取消后清理，不进入数据库或备份；文件选择与复制由当前浏览器处理。

## 7. Unity 局域网设备日志

### 7.1 准备与搜索

1. Unity 项目需包含新版 `Assets/Test/Log`，启动场景使用已配置浏览器页面的 `StartupLogManager` 预制体。新增发现协议属于 AOT 程序集，**重新打 APK/iOS 包后才生效，仅更新热更代码不能加入此协议**；运行后仍可记录热更脚本输出的 Unity 日志。
2. 电脑与手机/iPad 接入可互通的 IPv4 局域网，设备应用保持前台；iPad 允许本地网络访问。预制体“启动时开启局域网日志读取”默认开启，也可由原有 `StartWebAccess()` / `StopWebAccess()` 控制。
3. 通过工具箱局域网地址打开“工具箱 → Unity 设备日志”；服务器本机也可用 localhost。点击“搜索局域网”，找到设备后点击该条目，读取其历史文件；无需手机确认、ADB、扫码或访问码。

默认探测 TCP 17523；若 Unity 预制体修改过端口，在“搜索设置与指定 IP”中同步修改。搜索按本机私有 IPv4 网卡与掩码计算，最多检查 1024 个地址、64 并发、25 秒总时限；显示每个网段实际检查数量、截断和超时，可取消搜索并保留上次结果。大网段未覆盖的设备可填写同网段 IP 后补查；不能填写网址或公网地址。

设备条目显示名称、型号、平台、版本、当前 IP 与固定编号短码。IP 改变后重新搜索、重新选择即可；重装应用或清除数据可能生成新编号。此编号不等同于硬件序列号。

### 7.2 阅读与下载

- “历史日志文件”选择设备已保留的文件；默认跟随最新文件，可关闭跟随并查看历史。轮换清理后的文件可能无法继续读取。
- 级别支持全部、警告与错误、仅错误/异常；关键词匹配整条正文和堆栈。点击记录展开详情，内容按纯文本显示。
- 每次最多预览文件末尾 256 KiB，界面最多显示最后 1000 条匹配记录，超出时给出提示。“复制匹配日志”复制本次预览匹配的完整记录与堆栈；需要完整原件时点击“下载当前文件全文”或“下载全部日志 ZIP”。下载位置由浏览器决定，不自动保存到工具箱数据库或服务器目录。
- 默认每 3 秒刷新，可暂停；“跟随最新记录”控制滚动。读取失败显示原因并保留上次成功内容，可手动刷新恢复。“结束读取”、切换设备或离页关闭旧会话；页面后台暂停请求。闲置约两分钟后重新选择设备；搜索结果超过约五分钟需重新搜索。

### 7.3 连接问题

| 现象 | 处理 |
|---|---|
| 搜不到设备 | 确认安装了新版完整包、预制体已运行且自动开启；应用保持前台，检查端口、本地网络权限、防火墙和 Wi-Fi 设备隔离。 |
| 显示范围截断或超时 | 查看网段报告，用指定 IP 补查；不会把未覆盖地址当作已检查。 |
| 提示访问受限 | 按第 0.6 节以 Lan 模式重启并使用服务器实际私网 IP，客户端须同网段；设备搜索由服务器执行。 |
| IP 已属于其他设备 | 重新搜索并选择；工具会核对稳定编号，避免读取旧 IP 上的其他设备。 |

| 日志为空或更新稍晚 | 检查设备写入级别、当前文件和网页筛选；文件写入存在刷新间隔。此功能只读取 Unity 已保存的日志，不读取 iOS/Android 全系统历史日志。 |

网络服务定位为可信局域网内只读调试；网页读取采用来源 IP 绑定的短期票据，原浏览器直接访问仍保留访问码。搜索与读取不能绕过路由器隔离或设备权限。验证范围与真机待验项见 [项目状态](PROJECT_STATUS.md)。

## 9. 开源工具接入

源码版更新后，关闭并重新启动工具箱，再刷新浏览器。在首页或工具箱选择以下工具。三者可在服务器本机或 Lan 模式的同网段浏览器使用；首次进入不会自动安装上游程序。

### 9.1 Yoinks 视频下载

1. Windows 完整工具箱内置下载引擎，默认无需安装 Yoinks 或填写路径。看到“内置下载引擎已就绪”后直接使用；要切换到其他版本，可在“组件设置”填写服务器上已有的 `yt-dlp.exe` / `ffmpeg.exe` 完整路径。点击“使用内置组件”清除手动覆盖并重新检测；缺少内置组件时仍可检测 PATH、`.yoinks/bin` 与已有 Yoinks 的 ffmpeg-static，未找到会明确提示。
2. 粘贴单个公开视频网页链接，点击“分析视频”，选择本次读取出的清晰度或“仅音频 · MP3”。没有 ffmpeg 时仅提供含音轨的单文件视频格式，不假装支持 MP3。
3. 点击“开始下载”，完成后点击“保存到电脑”。显示的是当前媒体流的下载量，合并或转换不计入此百分比；必须收到完整文件才显示完成。
4. 单项最多 1 GiB、十五分钟；分析结果五分钟过期，临时成品保留十分钟，最多三项。取消、离开页面会终止当前下载并清理；已完成的临时结果也会在离页时清理，先保存所需文件。

网页适配使用 Yoinks 的 yt-dlp 核心方案，不运行其终端 TUI；不读取浏览器 Cookie，不处理播放列表或登录/付费绕过。下载失败时检查网络、网站限制、yt-dlp / ffmpeg 版本，并重新分析。

源码开发者首次使用时，在项目根目录运行 `node scripts/prepare-media-tools.mjs`，显式获取锁定的 Windows x64 下载组件；`node scripts/prepare-media-tools.mjs --check` 可离线核对文件、大小、SHA256及许可。维护脚本支持有界分段续传，缓存位于 `build/media-cache`，成品位于 Git 忽略的 `vendor/media/win32-x64`；网页和日常启动不会联网安装或自行更新。发布构建会核验并带上这套组件及许可。版本、来源和源码链接见[开源接入说明](OPEN_SOURCE_INTEGRATIONS.md)。

### 9.2 FreeLLMAPI 模型对话

1. 在运行工具箱的服务器电脑安装并运行 [FreeLLMAPI](https://github.com/tashfeenahmed/freellmapi)。在上游管理页添加供应商 Key，或配置本地模型端点，再从 Keys 页面复制统一 API Key。
2. 打开工具箱的“连接设置”，填写服务器上的回环地址，例如 `http://127.0.0.1:3001/v1`（指工具箱电脑）；桌面版可按其实际端口填写，可能为 31415。只支持回环地址，路径固定为 `/v1`。填写统一推理 Key，不要填写管理页登录令牌。
3. 保存后点击“刷新可用模型”，选择模型，输入消息发送；也可按 Ctrl + Enter。原管理页在工具箱服务器电脑上管理供应商、路由和额度；远程网页隐藏回环管理链接。
4. “停止生成”保留已收到的片段，但不放入后续上下文；“清空对话”取消等待并清空本页内容。离页取消生成，迟到结果不能回填。发送时最多携带最近九轮完整问答，上下文最多 48000 字，单条和回答最多 12000 字，页面最多展示三十轮。

Key 只保存在工具箱后端当前进程内存，页面不回显，重启工具箱服务后需重填；更换地址时会清除旧 Key。可以在设置中主动清除。对话只保存在当前页面，不写入工具箱数据库或备份。消息会发往你配置的 FreeLLMAPI 及其供应商；免费开源不代表额度无限，费用、模型支持与上游取消行为以实际服务为准。此页只接入文本聊天，图像、视频和完整路由设置使用原管理页。

### 9.3 ArtCraft 创作台

1. 从 ArtCraft 官网或 Releases 安装 Windows 版本，在“应用设置”填写工具箱服务器上的 `ArtCraft.exe` 完整路径，检测并保存。
2. 选择文生图、图生视频或 3D 场景，填写主体、比例、风格等要求，点击“整理提示词”；可在右侧继续编辑，再复制。
3. 点击“打开 ArtCraft”，核对路径并确认。提示“已发送启动请求”后，在服务器电脑查看 ArtCraft 自己的窗口，粘贴提示词、选择模型和素材再创作。

此页整理提示词，不执行模型生成；提示词不会自动注入 ArtCraft。ArtCraft 的原生编辑器在独立窗口中运行，不能把纯网页预览当作完整编辑器。工具箱不读取其账号、模型 Key 或素材，也不结束应用进程。提示词离页后清空，应用路径单独保存在服务器本机。

## 10. 实时网速

1. 在“工具箱”或首页打开“实时网速”（`/tools/network-speed`）。当前支持 Windows 服务器电脑，无需安装额外依赖或管理员权限；首次读取需要几秒建立基线，出现有效采样后显示速度。
2. 在“观察网卡”选择要查看的网卡，默认优先在线物理网卡。下载和上传分别显示字节速度及对应比特速度，下方提供观察期平均、峰值和累计流量；网卡信息显示连接状态、物理/虚拟类型及链路协商速率。
3. “网速趋势”显示最近 60 秒有效数据，蓝色实线为下载，绿色虚线为上传，刻度随流量调整。失败、离线和计数复位会显示状态，恢复时重新建立基线，不把旧读数显示为实时速度。
4. “暂停采样”停止本页读取并保留最后读数；“继续采样”、切换网卡或“清空记录”开始新的观察统计。清空只影响本页内存，暂停时清空不会自动恢复。网卡被移除时保留原选择并提示重选，避免把另一网卡流量混在一起。
5. 页面进入后台时暂停读取，返回前台重新统计；离页取消读取，刷新页面即清空记录。服务端全部页面共享一个按需采集进程，十秒无人读取后停止，其他仍在查看的页面不受影响。读取失败可点击“重试”，也会自动尝试恢复；不支持的系统会明确提示。

这里统计的是**运行工具箱的电脑**。从手机或另一台电脑访问，看到的仍是该服务器的网卡，而非访问设备自身网速。数据包含局域网与互联网，VPN、虚拟网卡和物理网卡可能统计同一份流量，因此逐张查看，不合并求和。此工具不进行外站宽带测速，不抓包，也不区分单个应用。

字节按 1024 换算（KB/s、MB/s），比特按 1000 换算（Mbps、Gbps）；1 MB/s 约为 8.39 Mbps。链路速率只是网卡协商值，不代表实际下载速度或运营商带宽。平均值按本轮有效观察时长计算，累计量按所选网卡计数差计算，不包含暂停和失效的空档；记录不写数据库、配置或日志。


## 11. 端口查看

从首页或工具箱打开“端口查看”，默认每5秒读取运行工具箱的Windows服务器。页面显示TCP监听、UDP绑定、已连接TCP和总端点数量；局域网访问时，数据也属于服务器电脑。

1. 查看端口冲突时，在“本地端口（精确）”输入例如3000，列表显示占用该本地端口的进程名和PID。
2. “协议”可选择TCP/UDP，“范围”可切换监听端口/全部连接；搜索框支持进程名、PID或地址。列表每页100条，点击“复制”取得该行信息。
3. 点击“立即刷新”主动重读，取消“每5秒自动刷新”改为手动。进入后台/离页会中止在途读取，返回后按自动刷新设置恢复；失败保留上次快照并明确提示。

UDP只表示绑定端点，不表示已建立TCP连接。IPv4/IPv6通配地址不能证明外网可访问；进程名可能因权限或退出而不可用，PID会复用，快照并非原子事务。最多5000条，截断时会提示；服务器可复用2秒内成功结果，系统采集15秒超时后可重试。本工具不主动提权、不结束进程、不扫描远端，也不修改网络/防火墙。

此入口仅包含在完整工具箱的源码版本；已发布版本是否包含，以[项目状态](PROJECT_STATUS.md)为准。

## Unity persistentDataPath 文件（TASK-039）

1. 打开安卓无线调试，在“Unity 替换 persistentDataPath 中文件”选择在线设备，点击“读取应用”，按包名选择目标 Unity App，再点击“读取 persistentDataPath”。应用需要先运行一次创建目录；列表无法自动识别 Unity 应用。
2. 目录为当前 Android 用户的 `/storage/emulated/<用户>/Android/data/<包名>/files`。点击子目录进入，点击“返回上级”返回；切换 Android 用户后点击“重新定位根目录”。
3. 普通文件可“预览文本”或“下载”。预览只支持不超过256KiB的UTF-8文本；其他格式下载后查看。单文件下载/上传最多256MiB，单目录最多1000项，符号链接和特殊文件不可操作。
4. 添加：选择电脑文件，核对手机端文件名，点击“添加文件”，检查设备、包名、用户、完整路径与大小后“确认添加”。同名文件存在时拒绝添加。
5. 替换：先下载原文件备份，并由你关闭会写入文件的App；在目标文件行点击“替换”，选择电脑上的新文件，点击“核对并替换”，核对原/新大小与目标后“确认替换”。电脑文件名可与手机原文件名不同，手机目标名保持原名。
6. 替换前复核原文件SHA256，传送的临时文件核验后才提交。App仍可能并发改写；工具不会自动停止App或创建永久备份。取消或中断不能撤销已经提交的写入，请刷新核对。失败保留所选新文件，重新核对后可重试。
7. 找不到目录或权限不足时会明确报错，不把失败当空目录。厂商ADB限制、自定义persistentDataPath或内部私有目录不支持；不自动root、修改权限或清空应用数据。换设备/应用、离页或后台会取消本面板等待，手机内容不进入团队数据库或备份。

### 多 APK 安装队列

1. 在“APK 传送安装”选择一台在线手机；需要多台时勾选“多设备安装”并选择目标。
2. 选择文件时按住 Ctrl 一次选择多个完整 APK，列表按选择顺序排列，可移除单项。最多20包、20台设备，单包1GiB、整批4GiB，不接受AAB/APKS或分包集合。
3. 点击安装，核对全部文件名、大小、目标手机和安装项数，再确认。每个APK仅上传一次；全部结构检查通过后，最多两台手机并行，每台按文件顺序安装，不在同一台手机上并行调用安装器。
4. 结果逐“设备 + APK”显示。单项失败继续后续任务；点击“只选择失败安装项”，确认区列出明确失败且在线的组合，重新确认后只重试这些组合，不重装成功项。
5. 上传总限五分钟、每项安装五分钟、安装队列总限一小时。取消、断连、后台或离页终止活动和后续任务，全部线程退出后清理临时包；取消不回滚手机已经完成的安装。

采用install -r覆盖同包名应用并保留数据，不自动卸载、降级、授权或启动应用。同包名不同版本会按文件顺序尝试，版本回退或签名不一致可能失败，请核对所选文件；这里的多个APK指各自完整安装包，不是split APK合集。

## 06 图标与快捷方式
