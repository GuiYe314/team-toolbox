# team-toolbox 0.1.1 发布验收报告（2026-10-26）

## 结论

**通过。** v0.1.0 的发布缺陷（原生模块 ABI 不兼容导致装完起不来）已修复，
并在**与用户相同的环境**（系统 Node v24.19.0 / ABI 137 在 PATH 中）实测通过。

## 一、缺陷复现与定位

### 现象

用户安装 v0.1.0 后双击 `启动.cmd`，报：

```
Error: 无法打开数据库，请检查配置
    code: 'cannot_open'
    detail: '[Cannot open] The module ... better_sqlite3.node
             was compiled against a different Node.js version using
             NODE_MODULE_VERSION 127. This version of Node.js requires
             NODE_MODULE_VERSION 137.'
```

### 定位过程

| 步骤 | 证据 |
|---|---|
| 确认系统 Node 版本 | `C:\Program Files\nodejs\node.exe -v` → **v24.19.0**，ABI **137** |
| 确认随包二进制来源 | 安装包内 `better_sqlite3.node` 的文件日期为 2025-05-08（预编译包），对应 ABI **127** |
| 确认构建机 Node | 打包脚本在构建机上执行 `npm install --omit=dev`，预编译二进制按**跑 npm 时的 Node ABI** 挑选 |
| 确认无本地解法 | `better-sqlite3` v11.10.0 官方预编译仅覆盖 `node-v108/v115/v127/v131`，**无 ABI 137** → 用户机器无法自愈 |
| 排除其他原生模块 | `sharp`（`@img/sharp-win32-x64`）与 `@napi-rs/canvas` 均为 **N-API**，跨 Node 版本兼容；实测用 Node 24 加载均成功 |
| 验证 `node.exe` 自包含 | 单独复制 `node.exe` 到空目录可独立运行 → Windows 版把 V8/libuv/OpenSSL 静态链接，**单文件即可** |

**根因**：发布包把「原生模块的 ABI 兼容性」这个**构建机的属性**泄漏给了用户，
而这个属性本不该由用户承担。

## 二、修复方案

### 方案对比

| 方案 | 可行性 | 结论 |
|---|---|---|
| 让用户跑 `npm rebuild` | Node 24 无预编译包 → 需 Visual Studio Build Tools | ✗ 对「双击即用」不可接受 |
| 安装器检查 Node 版本 | 只能提示，不能根治；用户装 Node 24 照样崩 | ✗ v0.1.0 已证明无效 |
| 打包多个 ABI 的二进制 | 需为每个 ABI 各下载一份（各 1.7 MB），且仍有覆盖不到的版本 | △ 可行但维护成本高、覆盖不全 |
| **包内自带 Node 运行时** | 彻底摆脱对用户 Node 版本的依赖 | ✓ **采用** |

### 实现要点

1. **内置运行时**：`runtime/node.exe`（v22.22.2，83 MB）。
   Windows 版 node.exe 单文件自包含，因此包内**不需要** npm / ICU 数据 / corepack。
2. **装依赖必须用同一套 Node**：打包时把内置 dist 加到 `PATH` 最前面再跑
   `npm install` —— 否则装出来的二进制 ABI 又与包内 node.exe 对不上。
3. **启动脚本优先用内置运行时**，包内运行时缺失时才退回系统 Node（并警告 ABI 风险）。
4. **启动前自检**（`runtime/check.js`）：ABI 不匹配时给出可操作提示。
5. **安装器移除 Node 检查**：Node 已内置，这个检查挡不住真问题，反而拦住了
   完全不需要装 Node 的用户。
6. **浏览器等就绪再打开**（`runtime/open-browser.js`）：原先是「先开浏览器再启服务」，
   用户会先看到「无法访问此页面」还得手动刷新。

### 顺带修掉的打包脚本 bug

`Invoke-Native` 的参数名原为 `$Args` —— **PowerShell 自动变量**。
用作 `param` 名会被自动变量抢占，参数个数恒为 0，
`& $Exe @Args` 展开成空调用 → npm 打印 usage 并以退出码 1 结束。

症状极具迷惑性：报错指向「前端生产构建失败」，真正原因在几行之外。
改名为 `$ArgList` 后修复。这个 bug 一直潜伏，是本次重打包才暴露。
