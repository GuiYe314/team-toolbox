## 五、发布验证中发现并修复的致命缺陷

**现象**：第一次真实触发 `apply` 时，`apply.cmd` 一执行就报出大量
「不是内部或外部命令」，命令行被撕成碎片，换文件完全没有发生
（版本仍是 0.1.1、`apply.log` 为空、`pending.json` 仍在）。

**两个原因叠加**：

1. **换行用了 LF 而不是 CRLF**。cmd.exe 解析纯 LF 的批处理文件是坏的，
   会把相邻行粘在一起。
2. **脚本里含 UTF-8 中文注释**，而中文系统控制台按 OEM 代码页解读，
   把 `rem` 行按字节错切成几条「命令」去执行。

**为什么之前的沙箱验证没有发现**：验证脚本自己做了 `\n → \r\n` 替换，
把生产代码的缺陷掩盖了。**这是「测试替身与生产路径不一致」的典型案例** ——
手工验证时补上的那一小步，恰好就是缺陷所在。

**修复**：

- `buildApplyScript` 改为用行数组 + `join('\r\n')` 生成，杜绝裸 LF。
- 脚本内注释全部改为英文（纯 ASCII）；唯一保留的中文是 `启动.cmd` 这个文件名本身。
- 写入时前置 UTF-8 BOM，让 cmd 切到 UTF-8 以正确识别中文文件名 ——
  与打包脚本写 `启动.cmd` 用的是同一套约定。
- 新增 4 项单元测试钉住不变量：**不得出现裸 LF**、**除 `启动.cmd` 外必须纯 ASCII**、
  关键步骤必须在场、**不得出现 `timeout /t`**。

修复后重新打包，并用**包内自带的 `updater.js`** 再次生成脚本验证：
前 3 字节 `ef bb bf`、裸 LF 数量 `0`，随后在真实发布包上完整跑通换文件。

## 六、附带修正

- **打包脚本剔除 `*.test.js`**：后端测试与源码同目录，原先会被一起打进发布包
  （本版起为 0 个测试文件）。
- 清单读取超时 20s → 30s：实测 GitHub 资产下载 1.3–2.6 秒，
  但同一主机页面请求出现过 11 秒，超时太紧会把「网络慢」误报成「更新源不可达」。

## 七、遗留与说明

- **`spawn('cmd.exe')` 在本机验证环境中被安全策略拦截**，因此「服务自动拉起
  换文件进程」这一步是通过手工执行 `apply.cmd` 验证的。生产环境无此限制，
  且脚本本身的所有分支都已实测。
- 本版**必须手动安装一次**：v0.1.1 不含更新模块，无法自我升级。
- 未包含更新源默认值 —— 内网与出网环境需要的源不同，写死任何一个都会让另一半不可用。
