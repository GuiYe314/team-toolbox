## 后台升级缺陷与回滚证据

最初使用未经修改的 v0.3.0 发布包独立副本执行升级，下载、校验、自检及备份成功，但旧后台脚本未完成替换和重启。因此不能把本轮结果描述为“原版 v0.3.0 自动升级成功”。发现的因素包括 UTF-8 BOM/控制台代码页、后台外部命令管道阻塞和启动 CMD 未明确退出。

修复后，替换脚本为纯 ASCII、无 BOM、CRLF，Unicode 路径通过经过校验的环境传入，禁用延迟展开；无管道检查旧进程，重启显式使用后台 CMD `/c /nopause`。最终验证脚本 `build/verify-v031-upgrade-final.mjs` 从最终 v0.3.1 ZIP 创建两个全新副本，只将副本 package version 标记为 0.3.0 以产生升级条件；测试的是本版更新器，代码和运行时没有换回旧更新器。

两个副本路径均包含中文、空格及感叹号。成功分支完成 check/download/stage/apply 并重启为 0.3.1；失败分支只在隔离暂存目录注入 `process.exit(42)`，等待失败后恢复原程序和 0.3.0 测试标识。两者均复核合成文档、用户文件和本地更新源保留，回滚提示符合结果。最终 20 项检查通过，两个副本服务已停止；没有对真实开发项目执行 apply。

旧版用户应先完整备份并关闭服务，再手动安装或解压 v0.3.1，保留原 `data/`。v0.3.0 Release 需按版本政策保留资产并补充缺陷提示及修复链接；远端修改的实际结果仅记录在 PROJECT_STATUS。
