## 本轮修掉的问题

发布验证过程中暴露 5 个真问题，全部已修复并有回归覆盖：

1. **后端不托管前端** —— `express.static` 此前是注释掉的，生产部署下前端与 API 不同源。发布包改为后端单端口同时托管两者，前端用相对路径 `/api` 调用。附带实现 SPA 回退（history 模式深链刷新不白屏）与三档缓存策略（带哈希产物 immutable、index.html no-cache、vendor 短缓存）。

2. **`/assets` 路由与构建产物目录同名冲突** —— Vite 默认把产物输出到 `dist/assets/`，而前端恰有一条 `/assets` 路由（资源管理页）。`express.static` 优先处理，`GET /assets` 被当成静态目录请求 → 301 → 该目录下无 index.html → 404，**资源管理页直接打不开**。修法：Vite `build.assetsDir` 改为 `static`。

3. **`DB_PATH` 环境变量完全失效** —— `getDefaultDatabase()` 调 `createDatabase()` 时没传 path，而该函数默认参数是硬编码的 `'data/team-toolbox.sqlite3'`，**不读环境变量**。后果：日志打印的是环境变量指定的路径，实际打开的却是项目默认库，文件根本没被创建。表现极具迷惑性（「迁移没执行、表却都在」完全对不上账）。修法：显式传 `DB_PATH_RAW`，并新增 `db.test.js` 3 项覆盖。

4. **后端启动不自动迁移** —— 此前靠启动脚本先跑 `npm run migrate`。用户若手动 `node src/index.js`（或脚本被跳过），服务能起来但表不存在，资源接口报 `no such table: asset_versions`。修法：迁移纳入 `start()` 流程，**放在 `listen` 之前**（否则有一段窗口期接口全 500），迁移失败直接退出而非继续服务。

5. **缓存头未按预期生效** —— 最初的哈希正则写成 `\.[0-9a-f]{8,}\.`（要求扩展名前是纯 hex），但 Vite 产物名是 `名称-哈希.扩展`（哈希在扩展名**之前**且含 base64 字符）。修正为 `-[A-Za-z0-9_-]{8}\.` 后三档策略全部生效。

## 已知限制

- **无认证与权限控制** —— 按 [ARCHITECTURE 第 7 节](../ARCHITECTURE.md) 只面向受控本机/内网，不得暴露公网。
- **需要 Node.js 运行时**（v20.19+ 或 v22 LTS）。安装包在安装前检查（注册表 + 5 个常见安装位置，含 nvm/Volta/scoop），未检测到时询问是否继续；便携包由「启动.cmd」检查并提示下载链接。
- **视频缩略图与封面不可用** —— 构建环境无 ffmpeg，预览管线如实标记 `failed` 并说明原因。视频文件的上传、下载、版本管理均正常。
- 实时共同编辑（F-COL-001）与账号权限（F-SEC-001）为延期特性，本版不包含。
- 工具箱中除「比例锁定」外的具体小工具均为空状态框架。

## 构建环境事实

- **Inno Setup 6.7.3** 通过 `winget install JRSoftware.InnoSetup` 安装（用户级路径 `%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`，非 Program Files）。
- 本机**无 pwsh**（PowerShell 7），只有 Windows PowerShell 5.1 —— 脚本必须兼容 5.1，且 `.ps1` 与 `.iss` 文件需带 **UTF-8 BOM**，否则中文被按 OEM 代码页解读而解析失败。
- 本机**无 7-Zip**，压缩用 .NET `System.IO.Compression.ZipFile`。
- Inno Setup 的 Pascal Script 有若干非标准限制（详见 `installer/team-toolbox.iss` 内注释）：不支持动态数组、不支持逗号分隔多变量声明、`RegQueryStringValue` 是 4 参数且 SubKey 与 ValueName 必须分开。

## 回退

本版为首个正式版，无历史版本需升级。回退即删除程序目录。数据位于 `<程序目录>/data/`，安装包卸载默认保留该目录；彻底清理请手动删除。
