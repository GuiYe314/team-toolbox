- 项目：team-toolbox（团队工具箱）；基线日期：2026-10-16
- 性质：本文描述**目标行为**。截至基线日期项目仅有文档、未实现任何功能；实现进度以 [PROJECT_STATUS](PROJECT_STATUS.md) 为唯一来源。
- 配套：[DEVELOPMENT_PLAN](DEVELOPMENT_PLAN.md)（任务分解与阶段门槛）、[ARCHITECTURE](ARCHITECTURE.md)（技术约束与待决策清单）

## 1. 背景与范围

team-toolbox 是面向内部小团队的网页版工具集合。第一版（MVP）聚焦知识库：用 Markdown 文档沉淀团队知识，支持分类、标签、搜索与服务端持久化，首页展示最近更新。工具导航与卡片框架在本版落地，但**不实现任何具体小工具**。

**硬约束（适用于所有特性）**：

- C1 团队数据必须保存在服务端；禁止把浏览器 localStorage 当作团队共享数据库。
- C2 第一版无认证与权限，仅可在受控本机/内网环境运行；不得宣称无认证也能安全用于公网。
- C3 技术选型不依赖“最新版本”这一事实，具体栈由 TASK-001 决策（见 ARCHITECTURE 待决策清单）。

**版本范围**：

| 版本 | 范围 | 说明 |
|---|---|---|
| v0.1（MVP） | F-KB-001~008、F-NAV-001~002、F-OPS-001~002 | 完成门槛见 TASK-010 |
| 延期 | F-COL-001、F-SEC-001 | 单独标识，不计入 MVP 完成门槛 |

## 2. 编号规则

`F-KB-xxx` 知识库 / `F-NAV-xxx` 导航框架 / `F-OPS-xxx` 运行边界 / `F-COL-xxx` 协同（延期）/ `F-SEC-xxx` 安全（延期）。编号一经发布保持稳定：需求变更改内容不改编号；废弃特性在矩阵标注“已废弃”并保留编号，禁止复用。

## 3. MVP 特性明细

每个特性按固定字段描述：价值与优先级 / 目标版本 / 前置与输入 / 流程与输出 / 失败与恢复 / 安全考量 / 验收标准（可测试）。

### F-KB-001 新建 Markdown 文档

- **价值与优先级**：P0。团队知识沉淀的最小入口，缺失则知识库不成立。
- **目标版本**：v0.1（MVP）。
- **前置与输入**：进入“新建文档”页；输入标题（必填，去首尾空白后 1–100 字符）、正文（Markdown 文本，可为空，上限 1MB）、分类（可选，须为已存在分类）、标签（可选，每文档 ≤10 个）。
- **流程与输出**：提交 → 服务端校验 → 写入持久化存储并生成 id、version=1、created_at/updated_at → 前端跳转文档详情页并提示成功。
- **失败与恢复**：网络/服务错误时前端保留已输入内容（会话内草稿）并允许重试；校验失败返回字段级错误；服务端保证要么完整写入、要么不写入，不留半条数据。
- **安全考量**：正文按原文存储，仅在渲染时安全渲染（见 F-KB-002）；长度与结构在服务端校验。
- **验收标准**：1) 新建后列表与详情可见；2) 空/纯空白标题被拒并提示；3) 模拟断网保存失败后内容不丢失、重试可成功；4) 刷新页面与服务重启后文档仍存在（服务端持久化）。

### F-KB-002 编辑文档（含保存冲突处理）

- **价值与优先级**：P0。知识库的核心维护路径。
- **目标版本**：v0.1（MVP）。
- **前置与输入**：已存在文档；编辑页加载标题/正文/分类/标签及当前 version。
- **流程与输出**：修改后保存并携带 version；服务端比对一致则写入、version+1、更新 updated_at；不一致返回 409 及服务端当前内容。编辑页提供与最终渲染一致的 Markdown 预览。
- **失败与恢复**：冲突时提示“文档已在别处被修改”，提供【加载最新（丢弃本地修改）】与【基于最新内容覆盖保存（需再次确认）】两个选项；MVP 不做自动合并。普通保存失败的重试策略同 F-KB-001。
- **安全考量**：Markdown 渲染必须安全渲染：默认转义 HTML、仅白名单语法可用，防止存储型 XSS。
- **验收标准**：1) 保存后详情页与首页 updated_at 变化；2) 两个会话先后保存同一文档，后者收到 409 与明确选项；3) 选“加载最新”后内容与服务端一致；4) 含 `<script>` 的 Markdown 保存后渲染不执行脚本。

### F-KB-003 删除文档

- **价值与优先级**：P0。
- **目标版本**：v0.1（MVP）。
- **前置与输入**：已存在文档；删除入口位于文档页。
- **流程与输出**：点击删除 → 二次确认（显示文档标题）→ 服务端删除（含标签关联）→ 列表、搜索、最近更新均不再出现。
- **失败与恢复**：删除失败提示并可重试；确认框可取消。误删恢复走备份（F-OPS-002）；MVP 无回收站（回收站属后续增强，不承诺）。
- **安全考量**：二次确认防误触；接口仅接受已知文档 id。
- **验收标准**：1) 删除后列表/搜索/最近更新均不出现该文档；2) 取消确认则不删除；3) 与 F-OPS-002 联测：备份恢复演练可找回删除前内容。

### F-KB-004 分类管理

- **价值与优先级**：P1。横向组织文档。
- **目标版本**：v0.1（MVP）。
- **前置与输入**：分类名称（1–30 字符，同级唯一）；MVP 仅一级分类、不嵌套、上限 50 个。
- **流程与输出**：新建/重命名/删除分类；重命名不影响文档归属；删除分类时其文档 category_id 置空（变为“未分类”），确认提示受影响文档数。
- **失败与恢复**：重名/超限返回明确错误；操作失败可重试。
- **安全考量**：名称服务端校验，渲染转义。
- **验收标准**：1) 新建/重命名后列表正确反映；2) 删除分类后原属文档显示“未分类”；3) 重名被拒并提示。

### F-KB-005 标签管理

- **价值与优先级**：P1。跨分类检索的轻量维度。
- **目标版本**：v0.1（MVP）。
- **前置与输入**：编辑文档时输入标签名（1–30 字符）；保存时自动去空白、去重，英文字母统一小写合并。
- **流程与输出**：保存文档时同步文档-标签关联；列表页可按标签过滤（多个标签采用 AND 语义（同时包含所有所选标签），与分类筛选同时生效）；删除标签即解除全部关联。
- **失败与恢复**：超过单文档 10 个标签时提示；失败可重试。
- **安全考量**：名称服务端校验，渲染转义。
- **验收标准**：1) 添加/移除标签后正确显示；2) 重复标签自动合并；3) 按多个标签过滤仅返回同时包含全部所选标签的文档；4) 超过 10 个被拒。

### F-KB-006 搜索

- **价值与优先级**：P0。找回知识的主要手段。
- **目标版本**：v0.1（MVP）。
- **前置与输入**：搜索框输入关键词（非空，去首尾空白）。
- **流程与输出**：服务端按标题+正文匹配（实现方式待决策：SQL LIKE 或轻量倒排索引，见 ARCHITECTURE），结果按 updated_at 倒序、分页返回，展示标题、摘要片段、分类、标签。
- **失败与恢复**：空关键词不发起查询；查询失败提示可重试；无结果显示空状态文案而非报错。
- **安全考量**：关键词须参数化/转义处理，防止注入（依存储技术实现）。
- **验收标准**：1) 命中标题或正文的文档出现在结果中；2) 无结果显示空状态提示；3) 结果按更新时间倒序；4) 特殊字符关键词不引发错误或注入。

### F-KB-007 服务端持久化

- **价值与优先级**：P0（支撑性）。没有服务端持久化就不是团队共享知识库。
- **目标版本**：v0.1（MVP）。
- **前置与输入**：全部文档/分类/标签数据。
- **流程与输出**：写入部署机服务端存储（引擎由 TASK-001 决策：SQLite 或服务端文件等）；支持导出为独立于引擎的备份格式（JSON 或 Markdown+元数据，见 F-OPS-002）。
- **失败与恢复**：存储写入失败返回错误且不破坏已有数据；服务重启后数据完整。
- **安全考量**：数据文件位于部署目录并最小化权限；数据与备份不进版本库（.gitignore 排除 data/、*.db、backups/ 等）。
- **验收标准**：1) 重启服务后数据保留；2) 导出文件包含全部文档与元数据；3) 团队成员在另一浏览器/设备可见相同数据（证明不是 localStorage）。

### F-KB-008 首页最近更新

- **价值与优先级**：P1。默认入口反映知识库活跃度。
- **目标版本**：v0.1（MVP）。
- **前置与输入**：首页默认视图。
- **流程与输出**：按 updated_at 倒序展示最近更新的文档（标题、分类、标签、更新时间），默认 20 条，“查看更多”分页加载。
- **失败与恢复**：加载失败显示错误与重试；空库显示引导新建的空状态。
- **安全考量**：渲染转义。
- **验收标准**：1) 更新任一文档后其排到首位；2) 空库显示空状态；3) “查看更多”分页可用。

### F-NAV-001 工具导航与卡片框架

- **价值与优先级**：P1（框架性）。为后续小工具预留统一入口。
- **目标版本**：v0.1（MVP）。
- **前置与输入**：工具清单配置（名称、一句话简介、状态=规划中）。
- **流程与输出**：首页/导航呈现“小工具”区块，卡片仅展示元信息，点击进入对应空状态页（F-NAV-002）。**本版不实现任何具体工具功能。**
- **失败与恢复**：无（静态框架）。
- **安全考量**：卡片文案渲染转义。
- **验收标准**：1) 至少 2 张示例卡片展示正确；2) 卡片状态明确标注“规划中”；3) 不包含任何实际工具功能或伪造的成功交互。

### F-NAV-002 工具空状态

- **价值与优先级**：P1。
- **目标版本**：v0.1（MVP）。
- **前置与输入**：点击任一未实现工具卡片。
- **流程与输出**：统一空状态页：工具名 + “该工具尚未实现” + 返回工具箱入口；不向普通用户展示开发文档。
- **失败与恢复**：无。
- **安全考量**：无特殊项。
- **验收标准**：1) 空状态页文案准确；2) 不显示模拟数据或伪造运行结果；3) 返回导航路径可用。

### F-OPS-001 受控内网访问边界

- **价值与优先级**：P0（边界性）。在无认证前提下这是唯一安全边界。
- **目标版本**：v0.1（MVP）。
- **前置与输入**：部署配置（绑定地址/端口，经环境变量配置，样例见 env.example）。
- **流程与输出**：服务默认绑定内网/本机地址；README 与部署说明包含明确声明“仅限受控内网，禁止公网暴露”。
- **失败与恢复**：配置错误导致无法启动时给出可读错误提示。
- **安全考量**：本特性即安全边界本身；在 F-SEC-001 实现前系统无任何认证，公网暴露等于数据对公众可读写，必须杜绝。
- **验收标准**：1) 部署文档含边界声明；2) env.example 存在且 .env 被 .gitignore 排除；3) 默认绑定地址非公网通配，或文档对风险给出强制警告。

### F-OPS-002 备份与恢复

- **价值与优先级**：P0（数据安全）。
- **目标版本**：v0.1（MVP）。
- **前置与输入**：服务端存储中的全部数据。
- **流程与输出**：手动触发导出到 backups/（或配置的备份目录）；恢复按文档步骤导入备份重建数据；MVP 至少交付导出手段与恢复说明（由 TASK-009 实现）。
- **失败与恢复**：导出失败不损坏原数据；恢复前要求确认（恢复将覆盖当前数据）。
- **安全考量**：备份文件含全部团队数据，同样不进版本库，按内部资料保管。
- **验收标准**：1) 导出 → 清空 → 恢复后数据与导出前一致（演练一次并记录）；2) 恢复操作有覆盖确认。

## 4. 延期特性（不计入 MVP 完成门槛）

### F-COL-001 实时共同编辑（延期）

- 价值与优先级：P1（价值高但复杂度高，明确延期）。
- 目标版本：MVP 之后。
- 前置：MVP 交付且完成协同方案预研（TASK-D01）。
- 流程与输出（目标）：多人同时编辑同一文档，实时同步，冲突自动合并或低摩擦提示。
- 失败与恢复（目标）：断线重连后可同步；不可合并冲突回退人工决策。
- 安全考量（目标）：操作来源可识别（依赖账号体系方向）。
- 验收标准（目标，届时另行细化）：双端并发编辑最终一致。
- 说明：MVP 的乐观版本号（ARCHITECTURE 第 4 节）为其预留基础，但 MVP 不承诺任何协同能力。

### F-SEC-001 账号与权限（延期）

- 价值与优先级：P0（多角色/更开放部署的前提，但明确延期）。
- 目标版本：MVP 之后。
- 前置：MVP 交付且完成账号方案决策（TASK-D02）。
- 流程与输出（目标）：登录、登出、角色（如管理员/成员）、文档级权限。
- 失败与恢复（目标）：登录失败提示、会话过期处理。
- 安全考量（目标）：凭据安全存储与会话管理。
- 验收标准（目标，届时另行细化）：未登录/未授权访问被拒绝。
- 说明：在其实现之前系统只能运行于受控内网，任何场合不得宣称“无认证也可安全公网使用”。
