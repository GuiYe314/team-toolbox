# 开发计划（DEVELOPMENT_PLAN）

- 基线日期：2026-10-16
- 配套：[FUNCTIONAL_SPEC](FUNCTIONAL_SPEC.md)（特性与验收标准）、[ARCHITECTURE](ARCHITECTURE.md)（约束与待决策）、[PROJECT_STATUS](PROJECT_STATUS.md)（进度唯一来源）
- 规则：TASK-xxx 编号稳定；依赖为完成前置且整体无环；延期任务（TASK-Dxx）不计入 MVP 完成门槛；每任务完成后按 [AGENTS](../AGENTS.md) 规则更新状态与变更记录。

## 1. 功能开发阶段与验收门槛

按“先看到界面，再跑通知识库，再完善与交付”的顺序推进。阶段一至六属于第一版；阶段七、八为后续规划，不计入第一版完成标准。每阶段验收后再进入下一阶段，原有任务编号保持不变。各阶段实际进度只记录在 [PROJECT_STATUS](PROJECT_STATUS.md)。

| 阶段 | 目标与主要功能 | 对应任务 | 进入条件 | 可检查的交付与验收门槛 |
|---|---|---|---|---|
| 阶段一：项目基础 | 确认其余技术栈、SQLite 驱动与迁移方式、项目结构及环境配置 | TASK-001 | 文档基线可用 | 技术决策有依据；本机实际启动成功；配置示例不含密钥，真实环境文件被忽略 |
| 阶段二：界面与工具框架 | 左侧导航、首页框架、知识库页面框架、工具卡片及空状态 | TASK-004 | 阶段一通过 | 首页/知识库/工具箱可切换；至少两张规划中卡片可进入空状态并返回；窄屏可阅读、键盘可操作；不伪装已有业务功能 |
| 阶段三：知识库核心闭环 | SQLite 初始化与迁移、文档新建/查看/编辑/删除、Markdown 预览、保存失败与版本冲突 | TASK-002、TASK-003、TASK-005 | 阶段二通过 | 新建→保存→刷新→服务重启→再次读取内容一致；另一浏览器访问同一数据；删除须确认；断网保留编辑内容；双会话旧版本保存收到 409；Markdown 脚本不执行 |
| 阶段四：内容组织与查找 | 分类管理、标签管理与组合筛选、标题/正文搜索、首页最近更新与分页 | TASK-006、TASK-007、TASK-008 | 阶段三通过 | 分类删除后文档仍在；多标签 AND 筛选准确；标题/正文均可命中；空结果和失败有明确反馈；最近更新排序及分页正确 |
| 阶段五：数据保护 | 备份导出、校验与恢复、错误提示、恢复说明 | TASK-009 | 阶段四通过 | 在隔离测试数据上完成导出→删除测试数据→恢复，一致性通过；无效备份被拒；恢复失败不损坏原数据；覆盖前确认并备份现有数据 |
| 阶段六：第一版交付 | 集成验收、问题修复、内部部署验证、使用说明完善 | TASK-010 | 阶段一至五均通过 | 12 项 MVP 特性逐条有验收记录；受控目标环境访问成功；备份恢复演练有证据；真实启动说明可复现；文档和进度同步，无阻断问题 |
| 阶段七：团队账号与权限（后续） | 登录/退出、成员角色、文档访问与编辑权限 | TASK-D02 | 阶段六通过且账号方案确认 | 会话过期可处理；未登录/无权限的页面、接口均拒绝访问；权限变更后重新校验；未进入当前开发范围 |
| 阶段八：实时共同编辑（后续） | 同篇文档实时同步、冲突合并、断线恢复；在线成员/光标为待确认增强项 | TASK-D01 | 阶段七通过且协同方案确认 | 双端同时编辑最终一致；断线重连不丢已确认修改；协同通道也检查权限；用户可识别同步失败；未进入当前开发范围 |

阶段二只是界面框架，数据读写在阶段三验收。阶段五的备份演练只操作隔离测试数据，不能为了验收清空真实团队数据。阶段六先面向受控本机/内网交付，不承诺公网发布。

工具箱在第一版只保留框架。JSON 格式化、二维码等具体工具待用户明确选择后另拆任务，不计入现有任何阶段的交付承诺。在线成员、光标、历史版本也不能自动视为已确认范围。

每次开发任务应限定一个可验收交付物，结束时报告实际结果、使用模型及消耗积分；接口未提供积分时明确写“积分未提供，无法确认”，不能用 Token 或美元费用换算。检查状态、读取结果等管理调用与模型开发请求应区分，不能重复计费或假报零积分。

## 2. 任务明细

### TASK-001 技术栈决策与项目脚手架
- **交付物**：技术栈决策记录（更新 ARCHITECTURE 待决策清单：服务端语言/框架、SQLite 驱动与迁移工具（数据库已确定）、前端框架、Markdown 编辑器组件、安全渲染方案、搜索实现）；项目脚手架与目录结构；env.example；经验证后的本地启动说明（写入 USER_GUIDE）。
- **覆盖特性**：F-OPS-001（部分）。
- **依赖**：无。
- **验证**：决策记录完整且含理由；启动命令实际执行成功，输出摘要记入 PROJECT_STATUS。
- **完成条件**：待决策清单 MVP 必选项全部“已决策”；env.example 存在且 .env 被忽略。

### TASK-002 服务端基础与持久化层
- **交付物**：API 服务骨架；数据模型（Document/Category/Tag/DocumentTag，见 ARCHITECTURE 第 3 节）；SQLite 连接与初始化、建表迁移、外键约束、事务与参数化读写；version 字段与乐观并发基础。
- **覆盖特性**：F-KB-007、F-OPS-001（部分）。
- **依赖**：TASK-001。
- **验证**：健康检查接口；写入 → 重启 → 读取一致性检查；存储层条件写入冲突复现步骤（HTTP 409 待 TASK-003）。
- **完成条件**：SQLite 重启后数据保留；迁移与关联约束有效；失败事务回滚；不可写/忙锁错误明确；存储层版本冲突可检测。

### TASK-003 文档 CRUD API
- **交付物**：新建/读取/更新/删除接口；字段校验与统一错误码；409 冲突语义；分类/标签关联的读写支持。
- **覆盖特性**：F-KB-001、F-KB-002（API 部分）、F-KB-003。
- **依赖**：TASK-002。
- **验证**：接口级用例覆盖各特性验收中不依赖 UI 的条目（可用脚本或自动化测试）。
- **完成条件**：上述条目全部通过并记录证据。

### TASK-004 前端应用框架与导航布局
- **交付物**：页面骨架（首页、知识库列表、文档详情/编辑占位）；导航；“小工具”卡片区块；统一空状态组件。
- **覆盖特性**：F-NAV-001、F-NAV-002。
- **依赖**：TASK-001。
- **验证**：本地服务下页面可访问；卡片与空状态展示正确、无假数据。
- **完成条件**：F-NAV-001/002 验收标准全部通过。

### TASK-005 Markdown 编辑与文档页面
- **交付物**：新建/编辑页（Markdown 输入、预览、保存、失败重试与草稿保留）；删除入口与二次确认；保存冲突提示与两个处理选项。
- **覆盖特性**：F-KB-001、F-KB-002、F-KB-003（UI 部分）。
- **依赖**：TASK-003、TASK-004。
- **验证**：按 FUNCTIONAL_SPEC 验收标准在浏览器逐条手工测试并记录结果（含断网重试与双会话冲突场景）。
- **完成条件**：F-KB-001/002/003 验收全部通过。

### TASK-006 分类与标签
- **交付物**：分类与标签的界面与交互（编辑页选择/输入、列表过滤、分类管理操作）。
- **覆盖特性**：F-KB-004、F-KB-005。
- **依赖**：TASK-005。
- **验证**：分类重命名/删除迁移、标签去重/过滤、上限拦截等场景测试。
- **完成条件**：F-KB-004/005 验收全部通过。

### TASK-007 搜索
- **交付物**：搜索框与服务端查询实现（方案按 TASK-001 决策）；结果列表（标题、摘要片段、分类、标签、分页）。
- **覆盖特性**：F-KB-006。
- **依赖**：TASK-005（需有可编辑的文档数据）。
- **验证**：预置数据集上的搜索用例：命中、空结果、排序、特殊字符。
- **完成条件**：F-KB-006 验收全部通过。

### TASK-008 首页最近更新
- **交付物**：首页“最近更新”区块（默认 20 条、updated_at 倒序、“查看更多”）与空库空状态。
- **覆盖特性**：F-KB-008。
- **依赖**：TASK-005。
- **验证**：更新文档后排序变化；空库状态；分页加载。
- **完成条件**：F-KB-008 验收全部通过。

### TASK-009 备份导出与恢复
- **交付物**：导出脚本/命令（输出到 backups/ 或配置目录，格式与 F-OPS-002 一致）；恢复步骤文档；备份目录约定（配合 .gitignore）。
- **覆盖特性**：F-KB-007（导出部分）、F-OPS-002。
- **依赖**：TASK-002。
- **验证**：导出 → 清空 → 恢复 → 数据一致性演练一次，过程与结果记入 PROJECT_STATUS。
- **完成条件**：演练成功且有记录；恢复操作含覆盖确认。

### TASK-010 MVP 集成验收（阶段门槛）
- **交付物**：逐特性逐条验收执行记录；遗留问题清单；PROJECT_STATUS 与 CHANGELOG 更新；边界声明核查结果。
- **覆盖特性**：全部 12 项 MVP 特性（复核性覆盖，重点 F-OPS-001/002）。
- **依赖**：TASK-005、TASK-006、TASK-007、TASK-008、TASK-009。
- **验证**：按 FUNCTIONAL_SPEC 验收标准逐条执行；检查文档间链接有效性；核查 README/部署说明的“禁止公网暴露”声明在位。
- **完成条件**：**MVP 完成门槛**——F-KB-001~008、F-NAV-001~002、F-OPS-001~002 全部验收通过；延期特性 F-COL-001/F-SEC-001 及任务 TASK-D01/D02 不计入本门槛。

## 5. 里程碑判定

- **MVP 完成**：TASK-001~TASK-010 全部完成且阶段六门槛达成；延期任务不参与判定。
- **状态纪律**：每任务完成即更新 PROJECT_STATUS（含证据与下一任务）并追加 CHANGELOG；禁止将计划表述为实现。
