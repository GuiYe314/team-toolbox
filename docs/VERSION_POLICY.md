# 版本划分与发布约定

制定日期：2026-10-23。本文件规定 team-toolbox 的版本编号方式、发布资产形态与封版规则。实施状态以 [PROJECT_STATUS](PROJECT_STATUS.md) 为唯一来源，任务以 [DEVELOPMENT_PLAN](DEVELOPMENT_PLAN.md) 为准，功能范围以 [FUNCTIONAL_SPEC](FUNCTIONAL_SPEC.md) 为准。

## 版本归属

| 版本 | 名称 | 范围 | 边界 |
| --- | --- | --- | --- |
| v0.1 | MVP 基线 | TASK-001~TASK-010：知识库完整闭环（文档 CRUD、分类、标签、搜索、首页最近更新）、工具导航框架、资源管理子系统（资源库/版本/文件夹/预览管线/存储路径/导入导出/二维码分享）、受控内网部署边界、备份恢复 | 首个正式版为 `0.1.0`，标签 `v0.1.0` |

MVP 完成门槛为 DEVELOPMENT_PLAN 中 TASK-001~TASK-010。延期特性（F-COL-001 实时共同编辑、F-SEC-001 账号与权限，对应 TASK-D01/D02）**不计入**任何版本的完成判定。

v0.1 采用 `0.x` 编号而非 `1.0.0`，原因：系统**未内置认证与权限控制**，按 [ARCHITECTURE](ARCHITECTURE.md) 第 7 节只能部署在受控本机/内网。此阶段不具备面向外部署的条件，用 `1.0.0` 会传递错误预期。待 F-SEC-001 落地后再进入 `1.x`。

## 发布资产

每次正式发布产出**三份资产**，与源码归档（GitHub 自动生成）并列：

| 资产 | 名称 | 说明 |
| --- | --- | --- |
| 安装包 | `team-toolbox-Setup-<版本>.exe` | Inno Setup 编译的 Windows 安装程序，装到 `%LOCALAPPDATA%\team-toolbox` |
| 便携包 | `team-toolbox-<版本>.zip` | 解压即用的完整目录，含生产依赖与前端构建产物，无需安装 |
| 校验清单 | `team-toolbox-<版本>-SHA256.txt` | 三份资产的 SHA256 与字节大小，供下载后核对 |

不采用单文件 EXE。参考项目 TravelMap 用 PyInstaller 打包 Python 后端，而本项目后端是 Node.js —— better-sqlite3 与 sharp 都含原生模块，无法像 Python 那样冻结进单个可执行文件。改为「生产依赖随包分发 + 一键启动脚本」，形态不同但解决同一问题。

## 封版规则

1. `v0.1.0` 指向一次完整源码与文档提交。GitHub Release 保留同版本安装包、便携包、校验清单，源码由该标签对应归档。
2. 开发计划随发布提交保存。**未经对应验证的代码不得描述为「已完成/已实现/已通过测试」**；无法验证的一律写「未验证」。
3. 每次发布前完成真实启动验证：生产构建产物（非 dev server）可访问、健康检查通过、后端测试与前端验收全绿、便携包在**独立目录**解压后可启动。
4. 数据边界：SQLite 数据库、用户上传的资源文件、`.env`、密钥、`node_modules`、构建输出**一律不进入 Git 源码提交**，只作为发布资产分发。
5. 便携包与安装包**必须包含依赖**，否则用户在无网络环境无法启动 —— 这是内网部署的硬要求。
6. 升级前留完整备份。回退使用旧版程序与升级前的数据库及资源目录，不承诺旧版能读取后续 schema。
7. Release 不使用预发布标记（prerelease）发布正式版本；候选版本用 `-rc.N` 后缀并明确标注为候选。

## 数据位置与身份

| 项 | 约定 |
| --- | --- |
| 数据库 | `<项目根>/data/team-toolbox.sqlite3` |
| 资源文件 | `<项目根>/data/assets/<assetId>/<versionId>/` |
| 可配置存储路径 | 资源管理子系统支持镜像目录，见 PROJECT_STATUS 对应条目 |
| 端口 | 后端 3000，前端 dev 5173 |

安装版与便携版共用同一套路径约定，均相对**程序目录**（便携）或**安装目录**（安装版）解析，因此整个目录可整体移动或替换。
